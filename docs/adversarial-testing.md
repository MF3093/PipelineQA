# Adversarial Testing & Hardening Log

This document records deliberate stress tests performed against the QA Pipeline to identify failure modes and the hardening measures applied in response.

---

## Purpose

Demonstrate that AI-generated outputs are not accepted blindly — the system has been systematically attacked, broken, and strengthened through iterative adversarial testing.

---

## How to Run These Tests

1. **Injection tests:** Create a test story in your story source with the payload in the target field. Run Fetch + Parse. Verify redaction occurs and alert is shown.
2. **Malformed input tests:** Create stories with the specified defect. Run Phase 1. Verify correct flag/halt behavior.
3. **Crash recovery tests:** Start a run, interrupt at the specified point, restart. Verify recovery behavior.
4. **Gate bypass tests:** During a live run, provide the specified input at the gate. Verify the gate does not advance.
5. **Output quality tests:** Set up the described scenario (story + screenshots), run TC Generation. Verify the AI does not hallucinate or self-resolve.

## Interpreting Results

- **Pass:** System behaved as documented in "Expected Behavior"
- **Fail:** System did NOT catch the issue — requires hardening
- **Partial:** System caught it but the user experience was poor (e.g., unclear error message)

All failures must result in a rule update, prompt adjustment, or logic change before the test is marked resolved.
